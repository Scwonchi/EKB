# HTTP API: как написать свою страницу или клиент

Документ для тех, кто делает веб-страницу оператора, мобильное приложение или
интеграцию. Полное формальное описание — `api/openapi.yaml` (OpenAPI 3.1): по нему
можно смотреть API в любом просмотрщике OpenAPI и генерировать клиентский код.

Эталонный сервер — `server/server.py`, адрес API — `http://<сервер>:8080/api/v1`.
Его собственная страница (`server/web/index.html`) — пример клиента этого API.

## Быстрый старт без железа

```sh
python server/server.py                    # сервер, API на http://localhost:8080/api/v1
python tools/sim_device.py --count 2       # два имитатора устройств с людьми и тревогами
curl http://localhost:8080/api/v1/devices
curl -N http://localhost:8080/api/v1/events
```

## Как устроен клиент

Удобнее всего строить клиент на потоке событий:

1. Подключиться к `GET /api/v1/events` (Server-Sent Events).
2. Первое событие — `snapshot`: все устройства, последние цели и до 100 тревог.
   По нему нарисовать начальное состояние.
3. Дальше применять события `device`, `status`, `tracks`, `alarm`, `path`.
4. При обрыве `EventSource` в браузере переподключается сам (через 3 с), и снова
   приходит `snapshot` — состояние полностью заменяется, ничего досчитывать не нужно.

```js
const api = "http://localhost:8080/api/v1";
const es = new EventSource(`${api}/events`);
const on = (name, fn) => es.addEventListener(name, e => fn(JSON.parse(e.data)));

on("snapshot", s => { /* s.devices, s.tracks, s.alarms */ });
on("device",   d => { /* устройство подключилось или отключилось: d.online */ });
on("status",   e => { /* e.device_id, e.status */ });
on("tracks",   t => { /* t.device_id, t.targets — около 5 раз в секунду */ });
on("alarm",    a => { /* новая тревога (a.active) или снятая (!a.active) */ });
```

REST-методы — для разовых запросов. API только читает: устройства команд
не принимают (протокол устройств односторонний), поэтому методов `POST` нет.

| Метод | Что делает |
|---|---|
| `GET /api/v1/info` | версия API, время сервера |
| `GET /api/v1/devices` | все устройства с последним состоянием |
| `GET /api/v1/devices/{id}` | одно устройство |
| `GET /api/v1/devices/{id}/tracks` | последние цели радара |
| `GET /api/v1/devices/{id}/path` | трек передвижения устройства (точки `position`) |
| `GET /api/v1/alarms?active=true&limit=50` | журнал тревог, новые первыми |

Сервер разрешает запросы с любого источника (CORS, методы `GET` и `OPTIONS`),
поэтому страницу можно держать на другом веб-сервере или открывать как файл.

## Данные

**Device** — устройство: `id`, `online`, `address`, `firmware_version`,
`connected_at`, `status` (последний `Status` или `null`), `active_alarm_id`.
После отключения устройство остаётся в списке с `online: false`.

`id` назначает сервер — в данных устройства идентификатора нет. Для клиента это
непрозрачная строка: не разбирайте её, а в URL подставляйте через
`encodeURIComponent`. Эталонный сервер берёт IP-адрес устройства (`192.168.4.2`),
поэтому `id` сохраняется при переподключениях; другой сервер может выбрать иначе.

**Status** — не чаще раза в секунду: `radar_ok`, `people` (подтверждённых людей),
`detection_class`, `person_probability`, `position` (GPS или `null`), `satellites`,
`hdop` (или `null`), `heading_deg` (куда смотрит радар, или `null` без компаса),
`wifi_rssi_dbm`, `uptime_s`, `alarm_active` (признак тревоги на устройстве).

**Tracks** — на каждый снимок устройства, около 5 раз в секунду: `targets` (до 6),
`learning_background` (идёт запоминание фона — целей нет), `background_cells`.
У каждой цели:

| Поле | Значение |
|---|---|
| `id` | номер цели, сохраняется, пока она видна — удобно для следа |
| `distance_m` | дистанция от радара, до ~6 м |
| `angle_deg` | угол от оси радара, −60…+60, плюс — вправо |
| `bearing_deg` | азимут на цель от севера или `null` без компаса |
| `confirmed` | `true` — человек подтверждён; `false` — цель ещё проверяется |
| `detection_class` | `moving` / `stationary` для подтверждённых, иначе `unspecified` |
| `hit_ratio` | доля кадров, в которых цель видна, 0…1 |
| `speed_mps` | скорость, м/с |

Если событий `tracks` от устройства нет дольше 3 с — данные устарели, показывайте
«нет данных», а не последнюю картинку.

**Alarm** — тревога. Устройство не шлёт событий тревоги, а только признак
`alarm_active` в каждом снимке; тревогу создаёт сервер, когда признак становится
`true`, и снимает, когда он становится `false` (устройство держит его ещё 5 с
после ухода человека). Событие `alarm` приходит дважды: с `active: true` и потом
с `active: false` и `cleared_at`. `id` уникален в пределах сервера
(`устройство-номер`), его тоже не разбирайте. Поля положения — на момент
обнаружения (`detected_at`); где человек сейчас, смотрите по `tracks`.
`target_position` есть только при работающих GPS и компасе, точность — несколько
метров. Если устройство отключилось во время тревоги, она остаётся активной до
его следующего снимка.

**Общие правила**: время — ISO 8601 в UTC (`2026-10-20T10:15:30.125Z`); величины,
которые нельзя вычислить, равны `null` (поле не пропадает); новые поля могут
появляться без смены версии — незнакомые поля игнорируйте.

## Как нарисовать трек

`GET /api/v1/devices/{id}/path` — точки `{t, lat, lon, heading_deg}` с запуска сервера
(новая — при сдвиге на 0,2 м или повороте на 15°), дальше — событие `path` на каждую новую
точку. У разведчика в помещении это не GPS, а одометрия: точка старта плюс поворот по
гироскопу и сдвиг от источника перемещения; `status.satellites = 0`. Для рисунка
переведите в метры от первой точки (`x = Δlon·111195·cos(lat0)`, `y = Δlat·111195`),
север вверху; люди — `target_position` из тревог этого устройства.

## Как нарисовать радар

Радар видит сектор ±60° на 6 м. Для точки цели при радаре в точке (`ox`, `oy`)
экрана, оси радара вверх и масштабе `k` пикселей на метр:

```js
const a = t.angle_deg * Math.PI / 180;
const x = ox + t.distance_m * k * Math.sin(a);
const y = oy - t.distance_m * k * Math.cos(a);
```

Чтобы север был вверху, вместо `angle_deg` подставьте `bearing_deg`
(а сектор радара поверните на `status.heading_deg`).

## Ошибки

Тело ошибки: `{"error": {"code": "...", "message": "..."}}`. Решения принимайте по
`code`, `message` — для человека, формулировка может меняться.

| HTTP | `code` | Когда |
|---|---|---|
| 400 | `bad_request` | неверный параметр `limit` |
| 404 | `device_not_found` | устройство не известно серверу |
| 404 | `no_data` | от устройства ещё не было снимков |
| 404 | `not_found` | нет такого пути |

## Версии

Версия в пути: `/api/v1`. В пределах v1 поля и события только добавляются.
Удаление, переименование или смена смысла поля — только в `/api/v2`, и сервер
тогда отдаёт обе версии, пока клиенты не перейдут.

## Свой сервер вместо эталонного

Сервер другого автора совместим со всеми клиентами, если он принимает устройства
по `docs/device-protocol.md` и отдаёт этот API. Проверка:

```sh
pip install pyyaml jsonschema
python tools/sim_device.py --count 2 &
python tools/check_api.py http://localhost:8080
```

`check_api.py` вызывает все методы, проверяет коды, ошибки, CORS и поток событий и
сверяет каждый ответ со схемами из `api/openapi.yaml`. Код выхода 0 — сервер совместим.

Типы для TypeScript можно получить из `api/openapi.yaml` любым генератором OpenAPI,
например `npx openapi-typescript api/openapi.yaml -o api.d.ts`.
