# Трек дронов для iot-go

Страница для оператора поверх **сервера iot-go**: трек передвижения каждого устройства,
курс, на сколько повернулся, пройденный путь, люди на треке. Сам iot-go не меняется.

```
python iotgo_client/iotgo_view.py --iotgo 127.0.0.1:8080      # адрес HTTP API iot-go (server_http)
открыть http://localhost:8090/
```

Нужен только Python 3.8+. Ноутбук с iot-go может быть другим — укажите его адрес в `--iotgo`.

## Почему так

- iot-go отдаёт веб-клиентам только **список устройств** (`GET /api/v1/devices`) и **поток
  снимков** каждого (WebSocket `/api/v1/devices/{id}`, JSON). Истории нет — трек собирает
  страница из снимков: `position` (где устройство) и `heading_deg` (куда смотрит).
- WebSocket iot-go принимает только страницы **со своего же адреса** (same-origin, библиотека
  coder/websocket). Страница, открытая с диска или другого порта, получит отказ.
  `iotgo_view.py` отдаёт страницу и пробрасывает `/api/...` в iot-go: для браузера всё на
  одном адресе. Если у iot-go появится своя веб-страница — `index.html` можно положить туда
  как есть (все запросы относительные: `/api/v1/...`).

## Что считает страница

| | Откуда |
|---|---|
| Трек | точки `position`: новая — при сдвиге на 0,2 м или повороте на 15° (до 5000) |
| Курс | `heading_deg` при `heading_valid` |
| Повернулся | сумма изменений курса между снимками: +370° — полтора оборота по часовой |
| Пройдено, от старта | длина трека и расстояние от первой точки |
| Люди на треке | подтверждённые цели: точка дрона + (курс + угол цели) + дистанция; ближе 1 м — один человек |
| Серые точки | текущие неподтверждённые цели радара |

Трек хранится в браузере (localStorage) и переживает перезагрузку страницы; «Очистить трек» —
начать заново, «Скачать трек» — GeoJSON (линия трека и точки людей; открывается в QGIS,
geojson.io, Яндекс Конструкторе карт).

## Откуда координаты у разведчика

В помещении GPS нет: разведчик сам считает `position` — точка старта, заданная оператором
(`home 55.751244 37.618423 90` в мониторе порта: широта, долгота, куда смотрит дрон), плюс
поворот по гироскопу и сдвиг (`move`, позже — датчик оптического потока). Подробно —
`radar_nn/rescue_scout/README.md`, раздел «Трек передвижения дрона».

## Ограничения iot-go, которые видны на странице

- **Идентификатор устройства.** Нынешний iot-go выдаёт новый UUID на каждое TCP-подключение
  (имя — `device_<адрес:порт>`): после обрыва связи устройство появится новой карточкой с
  новым треком. iot-go с рукопожатием Syn/Ack (`docs/iot-go/device-protocol.md`) хранит
  идентификатор по MAC — трек продолжится в той же карточке.
- Через ретранслятор у всех устройств один адрес (ретранслятора) — различаются по UUID.

## Проверено

Без настоящего iot-go (его зависимости здесь не скачать): на имитаторе его HTTP/WebSocket API
с тем же JSON (`internal/transport/ws/telemetry.go`) и той же проверкой Origin — страница через
`iotgo_view.py` получает снимки двух устройств и рисует треки; напрямую с другого порта
WebSocket отклоняется, как у iot-go.
