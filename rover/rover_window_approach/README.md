# rover_window_approach — подъезд к красному окну

Ровер сам находит камерой красное окно (прямоугольную рамку на стойках) и останавливается
перед ним так, чтобы его продольная ось проходила через окно. Это признак зачёта кейса 3:
«ровер выезжает к обручу, найденному камерой ровера; остановка не дальше 1 м от обруча,
продольная ось ровера проходит через обруч» (критерии B2.3, B2.4).

Нужны камера, одометрия `/odom` и меканум: ровер одновременно едет вперёд, вбок и
поворачивается. Nav2, карта и лидар не нужны.

## Какая камера

Окно стоит высоко (низ рамки примерно на уровне пояса), а штатная камера ровера — низко и с
объективом «рыбий глаз». Поддерживаются оба варианта, выбор — в `config/window_approach.yaml`:

| | Веб-камера на второй Raspberry Pi (по умолчанию) | Штатная камера ровера |
|---|---|---|
| `frame_source` | `http` | `service` (или `topic`) |
| `lens_model` | `pinhole` | `ideal` или `calibrated` |
| Где стоит | на мачте, выше ровера, наклонена вверх | низко, спереди |
| Окно в кадре | до ~0,8 м от окна | окно на 1,2 м уходит за верх кадра рано, дальше — по одометрии |
| Настройка | угол обзора и наклон — сервисом `~/calibrate` | угол объектива; точнее — шахматной доской |

Веб-камера выше и смотрит вверх, поэтому видит окно почти до самой остановки, и у неё обычный
объектив. С ней остановка — в 0,8 м от окна (`stop_distance_m`).

Окно на площадке — красная рамка примерно 85 × 70 см, центр на высоте 1,2 м: для низкой штатной
камеры это слишком высоко (в имитации 26 из 27, ближний подъезд почти вслепую).

## Как работает

1. **Выпрямление кадра.** Кадр пересчитывается так, будто камера смотрит строго
   горизонтально: у веб-камеры убирается наклон, у «рыбьего глаза» — ещё и бочка. Тогда
   вертикальные края окна в кадре вертикальны.
2. **Поиск.** Красная маска (HSV), контур с дыркой (рамка), четырёхугольник. Окна нет — ровер
   поворачивается на месте, сначала в ту сторону, где видел окно последний раз.
3. **Где окно.** По каждому столбцу над проёмом ищется край верхней и нижней планки с долями
   пикселя; через эти точки — прямые верха и низа. Расстояние между прямыми на левом и правом
   крае даёт расстояние до каждого края (известна высота рамки), их положение в кадре —
   направление. Два края — две точки на полу; середина — центр окна, перпендикуляр — нормаль.
4. **Не то красное.** Рамка берётся, только если её ширина сходится с шириной окна, а низ —
   с высотой окна над полом. Сплошные красные предметы (ящик, мяч) не проходят — у них нет
   дырки. Такая же красная рамка на полу не проходит по высоте. Из подходящих — ближайшая к
   прошлой оценке.
5. **Подъезд.** Цель — точка на нормали окна в `stop_distance_m` перед ним, ровер смотрит в
   окно. Вперёд, вбок и по углу — пропорциональный регулятор с ограничением скоростей. Пока
   ровер далеко от оси окна, он смотрит на центр окна (окно не уходит из кадра), у оси —
   разворачивается по нормали.
6. **Вблизи.** Если окно ушло за верх кадра, а ровер уже выровнен и до окна меньше 1,3 м,
   остаток пути он проходит по одометрии. Не выровнен — отъезжает назад, пока окно снова не
   влезет в кадр.
7. **Готово**, когда положение в пределах 5 см и угол в пределах 3° держатся 0,5 с.

Команды идут в `/cmd_vel_nav` через twist_mux: ручное управление (`/cmd_vel_teleop`) их
перебивает. Не запускайте одновременно с Nav2 — он пишет в тот же топик.

## Веб-камера на второй Raspberry Pi

На второй Pi нужны только Python 3 и OpenCV, ROS не нужен:

```bash
sudo apt install python3-opencv
scp rover_window_approach/webcam_server.py pi@rover-cam.local:~/
python3 ~/webcam_server.py --device 0 --width 640 --height 480 --port 8080
```

В браузере `http://rover-cam.local:8080/` — видео с камеры, чтобы навести её. Ровер берёт кадры
с `http://rover-cam.local:8080/frame.jpg` (адрес — в `http_url`). Сервер сам сообщает, сколько
миллисекунд назад снят кадр, поэтому часы двух Pi сверять не нужно. Нода отбрасывает кадры
старше `max_frame_age_s` (0,5 с).

Две Pi соединяются кабелем Ethernet напрямую или через одну сеть Wi-Fi. Кабель надёжнее: по
Wi-Fi кадры иногда задерживаются. Если камера стоит вверх ногами — `--rotate 180`.

Автозапуск на второй Pi — `/etc/systemd/system/webcam.service`:

```ini
[Unit]
Description=Webcam for window approach
After=network-online.target

[Service]
ExecStart=/usr/bin/python3 /home/pi/webcam_server.py --device 0 --port 8080
Restart=always
User=pi

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl enable --now webcam
```

## Запуск на ровере

```bash
colcon build --packages-select rover_window_approach
source install/setup.bash
ros2 launch rover_window_approach window_approach.launch.py
ros2 service call /window_approach_node/start std_srvs/srv/Trigger
ros2 topic echo /window_approach_node/status   # state, distance_m, axis_offset_m, yaw_to_face_deg, camera_error
ros2 service call /window_approach_node/stop std_srvs/srv/Trigger
```

Выпрямленный кадр с найденным окном и состоянием — `/window_approach_node/debug/compressed`
(rosboard или rqt_image_view). Он публикуется и до старта — по нему удобно навести камеру.

## Настройка на площадке (15 минут)

1. **Окно.** Рулеткой: внешняя ширина и высота красной рамки → `window_width_m`,
   `window_height_m`. Высота низа рамки над полом → `window_bottom_m`. По высоте рамки
   считается расстояние: ошибка высоты на 10% даёт ошибку остановки на 10%.
2. **Камера.** Высота объектива над полом → `camera_z_m`, насколько он впереди центра
   ровера → `camera_x_m`.
3. **Наклон камеры.** Камера должна видеть окно и с 3,5 м, и с 0,8 м. Для веб-камеры на высоте
   ~45 см и окна с центром на 1,2 м подходит наклон вверх ~30°. Проверьте по отладочному кадру: окно с 0,8 м целиком
   в кадре.
4. **Угол обзора и наклон точно.** Поставьте ровер прямо перед окном, измерьте расстояние от
   объектива до плоскости окна, запишите в `calib_distance_m`, перезапустите ноду и вызовите:
   ```bash
   ros2 service call /window_approach_node/calibrate std_srvs/srv/Trigger
   ```
   Ответ — `camera_hfov_deg` и `camera_pitch_deg`. Впишите их в конфиг, перезапустите ноду и
   повторите: второй проход уточняет.
5. **Цвет.** Если окно не находится или находится лишнее — посмотрите отладочный кадр и
   подстройте `red_s_min`, `red_v_min` (тусклый свет — меньше).

Ограничения скоростей — `max_vx`, `max_vy`, `max_wz`; если моторы не трогаются на малых
скоростях — увеличьте `min_v`.

### Если всё-таки штатная камера ровера («рыбий глаз»)

```yaml
frame_source: service
lens_model: ideal
camera_x_m: 0.12
camera_z_m: 0.10
camera_pitch_deg: 0.0
stop_distance_m: 0.6
```

Круг изображения по любому кадру: `ros2 run rover_window_approach lens_calib --circle кадр.jpg`
→ `lens_circle_cx/cy/r`. Угол объектива `lens_fov_deg` уточняется тем же `~/calibrate` (повторить
2–3 раза). Точнее — калибровка шахматной доской, 12–20 снимков с разных сторон:

```bash
ros2 run rover_window_approach lens_calib доска/*.jpg --cols 9 --rows 6 --square 0.025 --out ~/fisheye.yaml
```

затем `lens_model: calibrated`, `lens_calib_file: /home/…/fisheye.yaml`.

## Проверка без ровера

```bash
cd src/motion/rover_window_approach
python3 -m rover_window_approach.sim                          # 27 попыток, веб-камера
python3 -m rover_window_approach.sim --lens-error --size-error 0.1
python3 -m rover_window_approach.sim --camera fisheye         # штатная камера ровера
python3 -m pytest test
```

Имитатор рисует кадр камеры с того места, где стоит ровер. В сцене окно 85 × 70 см с центром
на 1,2 м на двух стойках, под ним табличка. Вокруг помехи: красный ящик, мяч и такая же красная
рамка, стоящая на полу. У веб-камеры имитатора есть бочка, о которой нода не знает. Команды
исполняются на мекануме с ошибкой 5–10% и задержкой кадра.

Результаты (27 попыток: 9 стартов на 1,5–3,4 м, в том числе спиной к окну, × окно прямо и
под ±20°):

| Вариант | Зачёт | До окна | Ось от центра | Угол |
|---|---|---|---|---|
| Веб-камера | 27 из 27 | 0,82–0,84 м | ≤ 3 см | ≤ 1,5° |
| Веб-камера, угол обзора +5°, наклон −4°, размер окна +10% | 27 из 27 | 0,74–0,75 м | ≤ 2 см | ≤ 1,3° |
| То же, но размер окна −10% | 26 из 27 | 0,90 м | ≤ 2 см | ≤ 1,5° |
| «Рыбий глаз» | 26 из 27 | 0,67 м | ≤ 3 см | ≤ 1° |

Неудачи: с размером −10% окно издалека под углом 40° не прошло проверку размеров; «рыбий глаз»
потерял высокое окно вблизи. Размеры окна измерьте рулеткой — от них зависит и дальность остановки.

Ошибка в угле обзора и размере окна сдвигает точку остановки, но не ось. Последняя строка —
«рыбий глаз» без калибровки останавливается слишком близко к окну. Поэтому калибровка нужна.

**На ровере не проверялось.** Имитация не учитывает освещение площадки, другие красные рамки
на высоте окна, задержку Wi-Fi между двумя Pi и качество одометрии меканума на полу площадки.

Проверка распознавания на снимках с площадки (для таблицы метрик качества распознавания):

```bash
ros2 run rover_window_approach window_check кадры/*.jpg --hfov 70 --pitch 30 --camera-z 0.45 \
    --width 0.85 --height 0.7 --bottom 0.85 --out размечено/
```

Файлы, в имени которых есть `nowindow` или `bez`, считаются кадрами без окна: находка на них —
ложное срабатывание. В конце — доля найденных окон и доля ложных находок.
