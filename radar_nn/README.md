# Поиск людей радаром

| Папка | Радар | Как решает «человек есть» |
|---|---|---|
| **`rescue_scout/`** | **LD2450 + гироскоп (XIAO ESP32S3 Sense с камерой или ESP32-S3 без камеры)** | **разведчик для кейса «Операция — спасение»: секторное сканирование с остановками, карта обнаружения, видеопоток, журнал миссии — описание в `rescue_scout/README.md`; нейросеть на борту отделяет людей от ложных целей радара** |
| **`capsule/`** | **LD2410C (ESP32-S3)** | **капсула, сбрасываемая с носителя: лежит и слушает, находит и неподвижного человека (дыхание); правила по энергиям зон + нейросеть против помех (куст на ветру); связь через тот же ретранслятор — `capsule/README.md`** |
| `ld2450_search/` | **LD2450** (основной) | сопровождение целей: координаты, дистанция и угол до 3 человек |
| `ld2410c_nn/` + `train.py` | LD2410C | нейросеть по энергиям зон дальности (нужны записи для обучения) |

Плата-носитель для варианта на ESP32-S3 (под ЛУТ) — `hardware/scout_carrier/`.

## LD2450: `ld2450_search`

Подключение: LD2450 5V/GND, TX → GPIO18, RX → GPIO17 (GPS и компас — как ниже).
Нужна библиотека TelemetryProto из проекта `telemetry`; Wi-Fi и IP сервера — в начале скетча.

Как работает: радар даёт до 3 точек ~10 раз в секунду. Точка становится «человеком»,
если держится ≥ 2 с и видна в ≥ 50% кадров; пропуски до 3 с (неподвижный человек иногда
пропадает у LD2450) трек переживает. Ближе 0,3 м (корпус дрона) и дальше 6 м — не учитывается.
Тревога — при первом подтверждённом человеке, отбой — через 5 с без людей.
Азимут на человека = курс радара по компасу + угол цели, отсюда точка на карте.

Команды в мониторе порта: `bg` — запомнить фон (20 с никого в зоне: мебель, стены,
свои конструкции перестают давать точки), `bgoff`, `rx` — знак угла, `tracks` — все треки.
С сервера команд нет: протокол односторонний, фон запоминается только из монитора порта.

На сервер устройство 5 раз в секунду шлёт снимок `Telemetry`: состояние, GPS, курс, до 6 целей
и признак `alarm_active`. Тревогу и отбой сервер выводит из смены этого признака.

Проверка знака угла: встаньте правее оси радара (если смотреть туда же, куда он) —
угол должен быть положительным. Если отрицательный — команда `rx` (запоминается).

# Нейросеть для LD2410C — локальное обучение

```
radar_nn/
├── ld2410c_logger/ld2410c_logger.ino   скетч сбора данных (10 строк/с)
├── record.py                           запись CSV на компьютере
├── train.py                            обучение и экспорт model.h
├── nav_test/                           проверка и настройка GPS и компаса
│   ├── nav_test.ino
│   └── nav_core.h, nav_hw.h
└── ld2410c_nn/
    ├── ld2410c_nn.ino                  распознавание + координаты и направление
    ├── nn_core.h                       признаки + сеть (model.h кладёт сюда train.py)
    └── nav_core.h, nav_hw.h            GPS и компас (те же файлы, что в nav_test)
```

## Подключение

| Модуль      | Вывод модуля | ESP32-S3 |
|-------------|--------------|----------|
| LD2410C     | VCC / GND    | 5V / GND |
|             | TX / RX      | GPIO18 / GPIO17 |
| GY-NEO6MV2  | VCC / GND    | 5V / GND |
|             | TX / RX      | GPIO16 / GPIO15 |
| GY-27       | VCC / GND    | **3V3** / GND |
|             | SDA / SCL    | GPIO8 / GPIO9 |

Компас крепится стрелкой X туда же, куда смотрит радар, подальше (5+ см) от аккумулятора,
силовых проводов и моторов. Антенна GPS — керамикой вверх, ничего металлического над ней.

## GPS и компас (до обучения сети, один раз)

Прошить `nav_test/nav_test.ino` и пройти шаги из комментария в начале скетча:
знаки осей акселерометра, калибровка компаса (команда `c` или удержание BOOT 2 с),
направление вращения, север, проверка наклоном, склонение (`d11.5`).
Настройки сохраняются в памяти ESP — скетч `ld2410c_nn` подхватит их сам.
Калибровку повторять после любых изменений в сборке.

## 1. Установка (один раз)

Python 3.10 и новее, затем:

    pip install numpy pyserial          # TensorFlow не нужен: train.py обучает на numpy

## 2. Сбор данных

Прошить `ld2410c_logger.ino`, закрыть монитор порта, затем для каждой ситуации:

    python record.py --port COM5 --label pusto --seconds 120 --note "комната 1, вентилятор выкл"

Метки (папки в `data/`), латиницей:

| метка        | что записывать |
|--------------|----------------|
| pusto        | никого нет, разные помещения |
| dvizhetsya   | человек ходит, жестикулирует, 1–6 м |
| nepodvizhen  | сидит/лежит неподвижно, 1–6 м, в том числе за дверью |
| pomeha       | вентилятор, кондиционер, шторы, животное — без людей |

Рекомендации: записи по 60–120 с, на каждую метку минимум 10–15 минут суммарно,
радар стоит на севшем дроне в том же креплении, что и на испытаниях.

## 3. Обучение

    python train.py --person dvizhetsya,nepodvizhen

Скрипт покажет точность, матрицу ошибок, долю найденных людей и ложных тревог,
и запишет `ld2410c_nn/model.h`.

## 4. Прошивка

Нужна Arduino-библиотека **TelemetryProto** из проекта `telemetry` (связь с сервером на protobuf,
см. его README). В начале `ld2410c_nn.ino` указать Wi-Fi и IP сервера; пустой `WIFI_SSID` — без связи.
На сервер раз в секунду уходит снимок `Telemetry` (без целей — LD2410C их не даёт) с признаком `alarm_active`.

Открыть `ld2410c_nn/ld2410c_nn.ino` (рядом должны быть `nn_core.h`, `model.h`, `nav_core.h`, `nav_hw.h`), прошить.
В мониторе порта раз в секунду — класс и вероятности, при уверенном обнаружении — «ТРЕВОГА»
с координатами дрона, азимутом радара, дистанцией и примерной точкой цели, плюс строка
`ALARM,...` для программы оператора:

    ALARM,номер,класс,уверенность%,дистанция_см,шир_дрона,долг_дрона,спутники,HDOP,азимут,шир_цели,долг_цели,флаги

Флаги: 1 — есть GPS, 2 — есть курс, 4 — есть точка цели, 8 — магнитная помеха.
Точность точки цели: GPS ±3–5 м, направление ±60° (радар видит конусом и угла не измеряет).
